# php-terminal-cms

## Agent skills

### Issue tracker

Issues live as markdown files under `.scratch/<feature-slug>/` in this repo. The directory is created by whoever writes the first one, so a clean checkout has none — and a release archive never carries it (`bin/manifest.php`). See `docs/agents/issue-tracker.md`.

### Triage labels

The five canonical triage roles keep their default names, plus a repo-local `done`. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: `CONTEXT.md` + `docs/adr/` at the repo root. See `docs/agents/domain.md`.

## Project

php-terminal-cms — a line-based markdown publishing platform. `README.md` is the entry
point; `CONTEXT.md` holds the vocabulary and `docs/adr/` the decisions.

- `php bin/test` before any commit — it checks the PHP and JavaScript halves
  still agree with each other, and runs `tests/js-model.js`, which asserts the
  editor's model invariants (cursor, folding, reordering) without a browser.
- `shared/` holds single sources; `editor/langs.js`, both `theme.css` copies and
  `tests/editor-probe.html` are generated by `php bin/build`. Never edit a
  generated file.
- Touched the editor's DOM half? Open `tests/editor-probe.html` in a browser —
  it drives the real page through the writing loop and prints pass/fail. It is
  the only test `bin/test` cannot run for you.
- The line model exists in three implementations (JS importer, JS renderer, PHP
  renderer). Changing one means changing all three — see ADR-0003. That
  includes the inline markup: `Renderer::inline()` and `editor/editor.js`'s
  `inline()` have to emit the same bytes for the same line, link allowlist
  included, and `bin/test` compares them through `tests/js-inline.js`.
- Dialects live in `shared/langs.json` (the tables) and the CLI prompts in both
  `editor/editor.js` and `site/src/Line.php`. `bin/test` compares them through
  `tests/js-tables.js` and checks every prompt still round trips, so adding a
  dialect means adding it in every place or the suite says which one is missing.
- `editor/ui.js` is keyboard, mouse and DOM only; anything about the document
  itself belongs in `editor/editor.js`, where it can be tested in node. Every
  mutation goes through `render()`, which restores the editor's invariants —
  see the header comment in `ui.js` and ADR-0005.
- The version lives in `VERSION` and is written into `editor/index.html` as
  `<i class="ver">`; `bin/test` fails if the two disagree. Bumping a release
  means editing both.
- Comments in source files describe the system, not the history of deciding it.
  Rationale belongs in `docs/adr/`; a `.php` or `.js` file should not point at
  an ADR number.
